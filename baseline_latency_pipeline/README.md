# Albay Network Performance Analysis

This repository contains tools and a Jupyter Notebook to download, process, and visualize Ookla Open Data (network performance) for the Albay province in the Philippines.

## Folder Contents

This directory isolates the first step of the study—calculating the baseline network performance. Here is what you will find inside:

- **`download_ookla_data.py`**: A script that connects to Ookla's open AWS S3 bucket, downloads network performance data (in parquet format), and geographically filters it to the Albay bounding box.
- **`explore_albay_improved.ipynb`**: The main Jupyter Notebook. It loads the downloaded network tiles, performs a strict spatial join with municipality boundaries, calculates average baseline latencies/speeds, and renders a choropleth map.
- **`albay_admin3.geojson`**: The geospatial polygon boundaries for the municipalities/cities in Albay, used for the spatial join.
- **`albay_ookla_fixed_2024_q4.parquet`**: (Generated) The cached local network dataset.
- **`pyproject.toml` & `uv.lock`**: `uv` configuration files defining the exact Python dependencies and their resolved versions.
- **`.venv/`**: (Generated by `uv`) The isolated virtual environment containing all installed packages.

## Prerequisites

This project uses [uv](https://docs.astral.sh/uv/), an extremely fast Python package and project manager written in Rust. Using `uv` ensures everyone on the thesis team has the exact same Python environment and dependencies without the usual setup headaches.

### 1. Install `uv`
If you don't have `uv` installed, you can install it globally on your system:

**Windows (PowerShell):**
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**macOS/Linux:**
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 2. Project Setup

Once you have cloned this repository, navigate into the project directory and sync the dependencies. Because this project includes a `pyproject.toml` file, `uv` will automatically create an isolated virtual environment (`.venv`) and install all required packages (such as `pandas`, `geopandas`, `jupyter`, etc.) in seconds.

```bash
uv sync
```

## Usage Guide

There are two main steps to this analysis: downloading the dataset and exploring it via the Jupyter Notebook.

### Step 1: Downloading the Data

The `download_ookla_data.py` script connects to the Ookla AWS S3 bucket, downloads the parquet data for a given year and quarter, and filters the network tiles to only those inside the Albay bounding box. 

To run this script using our isolated `uv` environment, simply prefix your command with `uv run`. This ensures the script has access to `pandas`, `pyarrow`, and `s3fs` without installing them globally.

```bash
# Run with default arguments (Year: 2024, Quarter: 4, Service: fixed)
uv run download_ookla_data.py

# Or specify custom arguments (e.g., for mobile data):
uv run download_ookla_data.py --year 2024 --quarter 3 --service mobile
```
*This will generate a local `.parquet` file (e.g., `albay_ookla_fixed_2024_q4.parquet`), which is required before running the notebook.*

### Step 2: Exploring the Data

The `explore_albay_improved.ipynb` notebook loads the downloaded data, performs a strict spatial join with the municipality boundaries (`albay_admin3.geojson`), calculates baseline latencies and speeds, and visualizes them on a choropleth map.

You can run the notebook in two ways:

**Option A: Using your IDE (VS Code / Antigravity)** - *Recommended*
1. Open `explore_albay_improved.ipynb` in your editor.
2. Click the **Select Kernel** button (usually in the top right corner).
3. Choose **Python Environments** and select the Python interpreter located inside the `.venv` folder that `uv` just created.
4. Run the cells as normal!

**Option B: Running a local Jupyter Server**
If you prefer running Jupyter directly in your web browser, start the server using `uv run`:

```bash
uv run jupyter notebook

# or if you prefer JupyterLab:
uv run jupyter lab
```
This command guarantees that the notebook server is launched strictly inside our isolated environment, ensuring all spatial and data libraries are perfectly loaded.
